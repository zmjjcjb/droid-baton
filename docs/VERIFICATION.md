# 验证记录

## 0.2.2 长任务等待

普通巡检记入本地日志。默认等待只在提问、异常、预算触发或最终审查等需要行动时返回。派发、回答和纠偏也使用更小的决策视图。

- 用一段真实长任务续接中记录的 8 次 0.2.1 等待回包回放新视图。相同事件集的 JSON 总体积约从 80.9 KB 降到 7.4 KB。其中 4 次是普通巡检，2 次是调用端主动设定的 50 秒等待超时。新版默认不返回普通巡检，省略 `timeout_s` 可避免 50 秒超时循环。
- 真实 Droid 分别完成两轮续做及检查失败后自动修复。两次运行共记录 4 次本地巡检，各只发出一次最终审查通知。通过本机已注册的 MCP 还验证了真实 Droid 派发、独立检查和最终接收。
- 用例覆盖等待跨过普通巡检、停滞通知去重、按通知 ID 等待新事件、问答选项、保留独立验收记录及 CLI 后台等待。用量需要在同类任务、同等完成条件下对照 Codex 会话日志。上述回放比较的是 JSON 字节数。

## 0.2.1 上下文开销优化

针对实测问题：监督者每次轮询都会把 Droid 的完整记录重新读进上下文。

### 问题基线（来自本机 Codex 会话记录）

`~/.codex/sessions/2026/11/10/` 下一个长期目标线程的实际数据：主线程 281 次模型请求、输入 token 累计 74,168,462（99.2% 命中缓存），上下文从 31,360 单调增长到 389,752，全程未触发压缩。同一目标下 `droid_wait`/`droid_supervise`/`droid_status`/`droid_send` 共 86 次 MCP 响应，其中 `droid_wait` 54 次几乎每次返回约 50 KB 全量快照；原始委派 prompt 在 MCP 输出中重复出现 21 次。

单次 `status()` 返回的构成（`~/.droid-baton/state.json` 中 `drun-66b6825f`）：总计 217.5 KB，其中 `work` 120.6 KB（`tools` 保留最近 100 次调用的完整输入）、`recent_events` 84.3 KB（30 条事件的完整载荷）。

### 改动

新增 `src/views.mjs` 精简视图层。`droid_status`/`droid_wait`/`droid_supervise` 经 MCP 调用时默认返回 `detail=summary`：只保留状态与计数、未结束的后台工作、最近 12 条事件的一行摘要、待答问题与验收结论。被折叠的数量以 `tools_not_shown`、`events_not_shown` 显式报告，不静默丢弃。`detail=full` 保留历史完整形状，面板与 CLI 沿用它。

`since_seq` 支持增量轮询：只返回 `seq` 大于游标的新事件，响应带 `last_seq` 供下次传入。底层 `~/.droid-baton/events/<run_id>.jsonl` 每条事件本就带单调递增 `seq`。

新增原地打转检测：统计连续相同工具调用（含参数顺序无关的稳定键），达到 3 次时写入停滞通知的诊断文本，并附最后使用的工具。

工具描述中明确监督者与执行者的分工，要求监督者不重复读取 Droid 正在修改的文件。

### 实测结果

对同一批真实运行（`state.json` 全部 20 个 run）：完整形状合计 1564.1 KB，精简后 123.4 KB，**减少 92.1%**。单 run 最大降幅 95.8%。

构造与实测捕获运行同构的负载（100 次工具调用 + 30 条完整事件）：完整 218.9 KB → 精简 12.7 KB，**减少 94.2%**；无新事件的增量轮询为 4.5 KB。

### 回归

新增 `tests/views.test.mjs`，覆盖精简视图体积与字段保留、`since_seq` 增量语义、未结束任务的判定、待答问题的裁剪、验收证据保留、连续重复调用计数与参数顺序无关性、停滞通知的成因诊断。当前完整回归为 51 项全部通过。

未声称的部分：节省量由本机捕获的真实运行负载与构造负载测得，尚未在一次新的真实长期目标会话中复测端到端的 Codex 输入 token 下降。
