# 长期任务监督

长期任务现在以**原始目标**为单位，同一个 run_id / session_id 可持续多轮推进。Droid 的一轮回复结束只进入判定流程，不再直接等同于目标完成。

## 如何启用

在 Codex 中明确说：

> 把这个长期任务交给 Droid，工作目录是……，让它读取任务文件……并负责预检、执行和续做。独立验收命令是……。开启本地监督，Codex 只处理异常、授权和最终验收。需要时打开执行监视终端。

主控应调用：

```json
{
  "cwd": "/absolute/project",
  "message": "原始目标、允许修改范围和验收要求",
  "checks": ["npm test"],
  "supervision": true,
  "terminal": true,
  "timeout_s": 21600
}
```

`terminal` 可省略。模型和权限默认沿用 Droid，不因为开启监督而自动更换模型或提高权限。

## 监督流程

```text
原始目标 → Droid 执行一轮 → 报告 continue / complete / blocked
  continue → 预算内继续同一目标、同一会话
  complete → 等待已观察后台工作结束 → 独立验收
              失败 → 预算内回同会话修复，再运行新的检查
              通过 → 交 Codex 审查需求覆盖 → accept → 整个目标完成
  blocked / 停滞 / 预算上限 → 返回原因，交 Codex 判断
```

缺失或自相矛盾的完成报告不会被当成成功。默认没有独立 checks 的任务也必须由主控审查产物；如果检查确实不适用，需要主控显式接收并记录依据。

每轮完成状态由 `droid-baton` JSON 代码块传回，这是模型的进展声明。文件变化、检查输出、原生工作事件和进程状态分别采集，不能以声明替代证据。

## Codex 怎样保持监督

主控使用 `droid_wait` 并省略 `timeout_s`，单次可等待至 3540 秒。任务完成、失败、提问或确需监督决定时提前返回。普通巡检写入本地事件日志，可在面板或终端查看。收到 `needs_attention=true` 时，根据通知作出决定后继续等待。

| action | 含义 |
| --- | --- |
| `watch` | 确认仍可等待的通知。同一段持续无进展只提示一次，新的进展后可再报告停滞 |
| `continue` | 运行中投递纠偏；本轮已结束时继续未完成事项 |
| `accept` | 审查目标覆盖，确认报告完整、后台状态及独立检查后接收 |
| `pause` | 显式暂停并停止当前受管执行，保留目标和历史 |
| `resume` | 显式恢复暂停或服务中断的目标，不重置原时限、轮次或 Token 预算 |

通知带 `attention.id`。处理时传 `attention_id` 可拒绝过期决定。并行等待时，从 `run_ids` 移除已经处理的终态 ID。需要等待其他运行时，可用 `after_attention: { "RUN_ID": "NOTICE_ID" }` 跳过已收到但尚未处理的通知。用户取消的任务不能用 resume 复活。

`droid_wait` / 后台 CLI wait 在收到监督通知时返回，让正在等待的 Codex 有机会分析和纠偏。**这不会凭空唤醒已经关闭或结束的 Codex 聊天。**Codex 不在线时，服务仍可在已有授权和预算内推进普通续做/修复；遇到需主控判断的情况或最终审查时会保留状态等待。没有添加定时唤醒、额外 Codex API 调用或计划任务。

## 默认预算与巡检

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `interval_s` | 300 秒 | 本地巡检间隔 |
| `stall_s` | 900 秒 | 没有内容、工具、原生子任务日志或文件进展时提醒；心跳不算实质进展 |
| `notify_progress` | false | 设为 true 时，普通巡检也请求主控确认 |
| `max_rounds` | 12 | 有界执行轮次，包含已观察到的原生后台完成交付轮次；最多可配 50 |
| `max_repairs` | 2 | 独立验收失败后的自动修复次数，最多可配 10 |
| `max_tokens` | 0 | 可选，0 不启用；按已返回轮次上报的 input+output 累计 |
| `auto_continue` | true | 是否自动进行范围内续做和检查失败修复 |
| `require_review` | true | 独立检查通过后仍交 Codex 审查 |

可用 `supervision: {...}` 覆盖默认值。总运行时限仍由 `timeout_s` 控制，默认 6 小时，可配至 7 天；按墙钟计时，暂停/恢复不会自动延长。

巡检读取本地事件、已观察进程和文件元数据，无需模型。巡检周期跨轮次累计。通常保留 `auto_continue: true`，有界续做和修复都由 Droid 处理。设为 false 时，每次 Droid 主动报告需要续做都会返回给 Codex。Droid 的 Token 上限根据已完成轮次的用量评估。达到上限后停止进一步自动执行。

停滞提示不会立即杀掉一个可能只是很慢的构建；主控结合最后工具、进展、心跳和后台状态决定等待或纠偏。确认通知后有抑制窗口，避免每秒重复唤醒主控。

## 后台工作跟踪

- 原生 Mission 的状态、feature 和 worker 事件会阻止过早完成。父会话一轮结束不覆盖仍运行的 Mission/worker。
- Task 的任务 ID、TaskOutput/TaskStop 结果及已观察子会话的持久化结束记录会用于判断。恢复旧子会话时，不把上一轮的结束记录误当成本轮结束。
- 本机 Droid 0.240.0 的 Task 默认异步，Execute 使用 `fireAndForget`。已按本机实际接口适配，而不是只按文档推测参数。
- 对 Execute 返回的后台 PID，在 Linux 验证进程归属、UID 和启动身份后跟踪；退出后留出短暂安静窗口，并等待可能出现的原生后续轮次。PID 被复用时不会误停新进程。
- 服务崩溃时，执行包装进程也持有所属后台进程身份，清理已经登记的脱离进程组任务。无法验证归属的 PID 不会被随意终止。
- “进程已退出”本身不能证明退出码为 0，成功仍看原生结果、产物、独立检查和主控审查。

原生文件格式和非结构化工具输出可能随 Droid 更新改变。无法确认的任务保持未完成并交主控处理，不猜测成功。不承诺追踪未被本桥观察到的远程任务或任意脱离关系的外部进程。长期常驻服务需要单独明确交接要求，不能把它当成普通应退出的后台构建。

## 终端

```bash
node src/cli.mjs watch RUN_ID
node src/cli.mjs watch RUN_ID --open
```

这是同一 Droid 执行的监视终端，显示输出、工具、目标轮次和监督通知，不会启动第二个写入同一会话的执行器。Ctrl+C 只关闭监视；停止工作用 cancel。Linux 图形环境可自动启动终端，无图形环境返回可手动执行的命令。

CLI wait 在需监督时退出码为 3，表示等待主控判断，不能视为任务成功或失败。网页面板也能显示监督状态并作出判断，但主路径仍是 Codex。

## 验证范围

已通过真实 Droid 两轮目标推进、真实失败检查后的自动修复、真实 fireAndForget 后台命令退出跟踪及主控接收。停滞、预算、任务关联、原生 Mission/Task 事件、原生子会话记录、防重复/过期决定和崩溃清理由自动化回归覆盖。真实大型 Mission、跨平台和数天运行尚未完成实测；不能把小任务联调解释为这些保证。
